# 竞品短视频素材分析流程

**版本 v3 ｜ 2026-11 ｜ 适用：陌生人社交 / 语音房 / 直播类 App 的买量素材研究**

---

## 一、这套流程解决什么

每周把竞品正在投的短视频素材抓下来，回答四个问题：

1. **在怎么拍** —— 形态、人物、场景、前 3 秒的钩子
2. **在说什么** —— 画面文案（花字）+ 口播稿全文
3. **往哪儿导** —— CTA 类型、产品界面的露出时点
4. **在复用什么** —— 同一句文案换画面、同一条素材反复重传

**不解决的问题**：投放效果。没有买量表就不做 install / CPI / 次日留存归因；这套流程只看"素材本身在讲什么"，不看"素材跑得好不好"。

---

## 二、一进一出

| | 内容 |
|---|---|
| **输入** | 竞品投放平台的一期素材（按产品分文件夹，mp4） |
| **输出 1** | 《竞品素材拆解表》—— 每条素材一行：形态 / 人物 / 场景 / 动作 / 语言 / 钩子 / 卖点 / CTA / 露出 / 规格 / 文案 / 拆解 / 置信度 + 6 帧预览图 |
| **输出 2** | 《口播转录表》—— 每条素材的口播原文 + 中文译文 + 是否有口播的判定 |
| **输出 3** | 《口径小结》—— 本周结构变化、可复刻的结论、与上周的口径差异 |
| **输出 4** | 累积台账 —— 下周只处理新增，不重复劳动 |

## 三、六个环节

| # | 环节 | 做什么 | 判据 / 方法 | 耗时（2000 条量级） |
|---|---|---|---|---|
| 1 | **采集** | 抓当周的素材清单并下载 | 按产品分目录；封面 + 时长 + 中间帧三重判重，重复的删掉并留记录 | 视量 |
| 2 | **素材去重** | 清掉"同一支片子被下了两次" | 跨格式同内容、封面+时长+中间帧 | 5–10 分钟 |
| 3 | **技术体检** | 每条素材提取元数据、截 6 帧预览图、算剪辑节奏、扫 AI 信号 | 时长/画幅/码率/切点/MD5；每 1/6 时长截一帧拼成一张图；帧差密度衡量切点节奏；AI 只认内容凭证 | 约 15 分钟 |
| 4 | **视觉打标** | 逐条看 6 帧图，按固定枚举填字段 | 枚举值固定、不自创；只看画面不猜声音；一句话中文拆解 ≤40 字 | 约 40 分钟（并行） |
| 5 | **口播转录** | 先查重、只转不重复的，再转写 + 判定 + 翻译 | 见第四节口径；转写后二次判定"真口播 / 歌词 / 片尾署名 / 无人声" | 约 2 小时 |
| 6 | **沉淀** | 本期结果并入累积台账，写口径小结 | 三张台账各按素材指纹去重 | 约 5 分钟 |

## 四、核心口径

### 4.1 什么算"重复"

四层判据，**从硬到软**：

| 层 | 判据 | 能挡住什么 |
|---|---|---|
| 文件 | 文件指纹完全相同 | 同一个文件被重复下载 |
| 画面 | 6 帧预览图的感知哈希接近 | 换编码、换分辨率重传 |
| 声音 | 音频指纹相似 + 时长接近 | **同一条旁白、换了画面**（复投的主要形态） |
| 文案 | 画面文案相同 + 时长相同 + 文本相似 | 同钩子换演员（**只有画面也相同时才可靠**） |

一句话：**"花字一样"不等于"口播一样"**——花字是钩子（3–5 字），口播是展开（30–90 字），换演员时口播稿常被重写。
实测：花字与时长都相同但画面不同的组里，只有约 43% 的口播文本一致。

### 4.2 什么算"有口播"

每条素材必须归到下面四类之一，不允许留空：

| 判定 | 含义 | 处理 |
|---|---|---|
| **真口播** | 有人真实在说话（口播、对白、旁白） | 进卡，原文 + 译文 |
| **无人声** | 纯 BGM / 纯画面 | 单列清单，与画面文案对照 |
| **歌词** | 音乐人声被识别成字 | 不进文案库，原文留档 |
| **片尾署名 / 幻觉** | 「感谢观看」「请订阅」「字幕由…」这类固定输出 | 剔除 |

判定不靠"画面看起来像"，一律走语音识别 + 二次判定；识别结果过短的会用更高精度的模型复查一遍。

### 4.3 打标字段（固定枚举，不自创）

形态（7 类）· 人物（5 类）· 语言（19 类）· 钩子（8 类）· 产品露出（4 类）· CTA（5 类）· 制作规格（4 类）· 卖点（8 类）
外加：画面文案原文（照抄原语言）· 一句话中文拆解（≤40 字）· 置信度（0.9 / 0.7 / 0.5）

## 五、交付物长什么样

**《竞品素材拆解表》** 四个页签：

1. **素材总表** —— 每条一行，带 6 帧预览图；低置信标红
2. **文案库** —— 画面文案去重，按出现次数排序（看谁在复投同一句）
3. **汇总统计** —— 形态 / 人物 / 钩子 / 卖点 / CTA / 语言 的分布
4. **产品画像** —— 每个产品一行：素材量、时长中位、主力形态、主力钩子、主力卖点、主力 CTA、无 CTA 比例

**《口播转录表》** 五个页签：口播总表 / 口播库（去重+出现次数）/ 无人声清单 / 统计 / 口播与花字的分工。

**《口径小结》** 不写"素材描述"，只写能拿去改脚本的结论。合格的结论长这样：

> - 某产品一条阿拉伯语文案复投 35 条，靠「一句话文案 × 换人换场景」堆量
> - 39% 的素材前 3 秒看不到产品，但 49% 结尾是下载引导，说明主流结构是「先藏产品 + 结尾硬落版」
> - 某产品口播率仅 76%，但平均口播 309 字（全场最长）：靠少数长口播剧情片承担内容

不合格的结论：**「画质清晰」「内容比较有趣」**——无法执行。

## 六、质量怎么保证

| 检查项 | 做法 |
|---|---|
| 不漏条 | 每条素材都要有判定；缺一条就报警 |
| 不误判 | 转写结果过"幻觉白名单"；判错的人工覆盖并记录原因 |
| 不超标 | 打标枚举越界数必须为 0；一句话拆解不超过 40 字 |
| 对得上 | 打标结果的编号/文件名与素材清单 100% 对齐，防错行 |
| 可追溯 | 每条都记录置信度；低置信集中在糊帧、纯界面归属、疑似 AI 质感 |

## 七、为什么越跑越快

三张累积台账按"素材指纹"存档：

| 台账 | 存什么 |
|---|---|
| 技术台账 | 每条素材的技术指标（时长/画幅/切点/MD5） |
| 打标台账 | 每条素材的 12 个视觉标签 |
| 语音台账 | 每条素材的口播原文、译文、判定，以及**音频指纹** |

下周新素材进来时，先比指纹：

- 文件指纹命中 → 直接继承
- **音频指纹命中（同一段旁白、换了画面）→ 直接继承**
- 都不命中才真正转写

实测：某一期 2094 条抓取，账面"新增"1530 条，实际只有 **1316 条**需要转写，其中 214 条是"换了壳的同一条声音"。
有了台账之后，同样量级的一期，转写量可压到 **300–600 条**。

## 八、能力边界

1. **只看得到公开投放素材**，拿不到投放后台数据；"地区"是数据源标注，不等于真实投放配置。
2. **口播来自语音识别**，人名、品牌名会有音转字误差（例如 App 名被听成同音词），译文为逐段翻译，长句适度压缩，不是逐字对译。
3. **AI 生成只认内容凭证**，没凭证不等于不是 AI；视觉判断只作为"疑似"线索，不作为定案。
4. **重复判定对"同一首 BGM、不同旁白"不敏感**：两条素材可能因为共用背景音乐被判为相近，因此音频判重额外加了时长约束与文本复核。
5. **结构分布会受样本构成影响**：只做头部几家 vs 全量所有竞品，结论不可直接横向比较，报告里必须注明口径。

## 九、换品类 / 换市场要改什么

| 要改的 | 说明 |
|---|---|
| 竞品清单 | 按产品分文件夹即可，流程不变 |
| 目标市场 | 影响语音识别的语种设置与翻译语向；多语种混批要按语种分批出稿 |
| 品类卖点枚举 | "卖点"这一列是按社交/直播品类定的（交友聊天、直播打赏、语音房派对…），换品类要替换这套枚举 |
| 视觉打标规范 | 形态、钩子枚举可沿用；若素材形态差异大（如电商带货），需补充对应枚举 |

## 附：术语

| 术语 | 含义 |
|---|---|
| 花字 | 画面上的大字文案，通常是钩子 |
| 口播 | 视频里的真人说话（口播、对白、旁白） |
| 印相 | 一条素材按时间轴截 6 帧拼成的一张预览图 |
| 复投 | 同一条素材或同一句文案，换包装反复投放 |
| 露出 | 产品界面第一次出现的时点 |
| 落版 | 结尾的品牌 logo / 下载引导画面 |
| 音频指纹 | 把音轨压成一串特征码，用来判断两段音频是否同一段 |
